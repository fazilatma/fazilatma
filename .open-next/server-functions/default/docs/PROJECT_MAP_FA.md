# نقشهٔ پروژه OptiBid (optibid.ir) — نقطهٔ ادامهٔ کار

> این سند پس از بازخوانی کامل کد در تاریخ ۱۴۰۴/۰۸/۱۴ (2026-11-05) نوشته شده است.
> هدف: هر کسی (یا هر نشست جدید) با خواندن این فایل بداند پروژه کجاست، چه چیزی ساخته شده و قدم بعدی چیست.

---

## ۱. خلاصه در یک نگاه

OptiBid دو محصول در یک اپ Next.js است:

1. **بازار درخواست خرید (Reverse Auction)**: خریدار درخواست ثبت می‌کند، فروشندگان پیشنهاد می‌دهند، خریدار یکی را انتخاب و پرداخت امانی (Escrow) می‌کند؛ پول تا تأیید دریافت کالا نزد پلتفرم می‌ماند.
2. **فروشگاه (Store)**: ویترین محصولات (لپ‌تاپ/قطعات کامپیوتر) با ایمپورت از دیجی‌کالا/ترب/CSV، ضریب قیمت سراسری، رفرش خودکار قیمت، سبد خرید و سفارش.

حالت نمایش سایت با `settings.siteMode` بین `store` / `request` / `hybrid` عوض می‌شود.

**وضعیت کلی:** پیاده‌سازی به‌شدت جلو رفته و تقریباً همهٔ جریان‌ها کد دارند (۱۸۷ فایل در `src`، ۶۴ روت API، ۳۴ صفحه). چیزی به اسم «نیمه‌کاره» در فهرست امکانات دیده نشد؛ کمبود اصلی، **داده و تست** است نه قابلیت.

## ۴. مدل داده (`OptiBidJsonData`)

همه‌چیز در یک شیء JSON ذخیره می‌شود:

- `users` — کاربر با نقش buyer/seller/admin، `kycStatus` و مدارک، اطلاعات بانکی (رمزنگاری‌شده)، `walletBalance`، `sellerModeEnabled`، `sellerMetrics`
- `requests` — درخواست خرید + فاکتورهای ارزش‌گذاری + برآورد قیمت + وضعیت
- `offers` — پیشنهاد فروشنده + ۴۰ فیلد مشخصات دقیق کالا (`OfferProductSpecs`) + تصاویر
- `orders` — سفارش امانی + کمیسیون + کد رهگیری + وضعیت چرخهٔ کامل
- `walletTransactions` / `transactions` (escrow) / `platformTransactions` / `withdrawals`
- `zarinpalPayments` — تلاش‌های پرداخت با authority و refId
- `storeProducts` + `priceHistory` + ضریب قیمت / `storeOrders`
- `messages`, `notifications`, `reviews`, `passwordResets`, `supportChatMessages`
- `catalogCategories` — درخت دسته‌بندی
- `settings` — حدود ۱۰۰ کلید: حالت سایت، کمیسیون، درگاه، اسلایدرها، متن‌های صفحه اصلی، پشتیبانی، نماد اعتماد، OAuth، پیشنهاد شگفت‌انگیز و…

**ذخیره‌سازی:** در Node روی فایل `OPTIBID_DATA_FILE` (پیش‌فرض `/tmp/optibid-data.json`) با نوشتن اتمیک؛ در Cloudflare روی KV با کلید `optibid:data`. رمزنگاری AES-256-GCM برای شبا/کارت/حساب/کلیدهای درگاه و مدارک KYC.

## ۶. جریان‌های اصلی (همه پیاده‌شده‌اند)

1. **ثبت‌نام و احراز هویت**: آپلود کارت ملی/شناسنامه/کارت بانکی → حساب `pending` → تأیید یا رد با دلیل توسط ادمین → فعال‌سازی ورود.
2. **درخواست خرید**: انتخاب دسته → فاکتورهای فنی و ارزش‌گذاری → برآورد قیمت → ارسال به همه یا دیسپچ دستی به فروشندگان منتخب.
3. **پیشنهاد فروشنده**: فرم ۴۰+ فیلدی مشخصات دقیق + تصاویر + مهلت تست و گارانتی؛ محدودیت تعداد پیشنهاد/حداقل پیشنهاد قابل تنظیم.
4. **انتخاب و پرداخت**: انتخاب پیشنهاد → آدرس → پرداخت با کیف پول یا زرین‌پال → نگه‌داشتن مبلغ در Escrow و کسر کمیسیون.
5. **ارسال و تحویل**: ثبت کد رهگیری → تأیید دریافت خریدار → آزادسازی مبلغ به کیف پول فروشنده.
6. **کیف پول و برداشت**: شارژ، برداشت با تأیید ادمین، تراکنش‌نامه.
7. **امتیازدهی**: نظر دوطرفه پس از معامله + امتیاز وزنی فروشنده (۳۰٪ اتکاپذیری، ۲۵٪ ارسال، ۲۵٪ رضایت، ۱۲٪ اعتماد، ۸٪ سابقه) با میانگین بیزی و آستانهٔ ورود به رتبه‌بندی.
8. **فروشگاه**: ایمپورت تک/گروهی/CSV از دیجی‌کالا و ترب → استخراج گالری و مشخصات → اعمال ضریب قیمت → رفرش دوره‌ای قیمت با هیستوری و سیگنال‌های رشد (SMA/EMA/RSI/MACD…) → سبد خرید → سفارش → پرداخت.
9. **پشتیبانی**: فرم تماس + چت زنده با ذخیرهٔ پیام و پاسخ ادمین.

## ۹. دیپلوی

- **Node/PaaS**: `npm run build` + `npm run start`، پورت ۳۰۰۰، دیسک پایدار برای `OPTIBID_DATA_FILE` و `OPTIBID_UPLOAD_DIR`.
- **Cloudflare Workers**: `npm run cf:prepare` / `npm run deploy:cf`؛ داده روی KV با binding `OPTIBID_KV`؛ خروجی آمادهٔ OpenNext در `.open-next/` کامیت می‌شود تا دیپلوی سریع باشد.

متغیرها در `.env.example`: مسیر داده، کلید رمزنگاری بانکی، حالت بازیابی رمز، زرین‌پال، OAuth گوگل/فیسبوک.

## ۱۰. وضعیت محیط فعلی (همین workspace)

- `npm install` انجام شد (۶۸۶ پکیج) و `node_modules` آماده است.
- `npx next dev` روی پورت ۳۰۰۰ اجرا شد و این مسیرها سالم پاسخ دادند: `/` ۲۰۰، `/shop` ۲۰۰، `/login` ۲۰۰، `/api/health` ۲۰۰ (storage: json-file)، `/admin/dashboard` ۲۰۰ بعد از ورود.
- `/requests` و `/admin/dashboard` بدون ورود → ۳۰۷ به `/login` (گارد درست کار می‌کند).
- **ورود ادمین**: نام کاربری `admin` / رمز `1234` (هاردکد در `src/app/api/login/route.ts`).
- **داده**: فایل داده خالی است؛ نه کاربر، نه درخواست، نه محصول. حالت سایت `store` با کاتالوگ قطعات کامپیوتر روشن و کاتالوگ لپ‌تاپ خاموش است.
- فایل `.env` وجود ندارد؛ بنابراین مقادیر پیش‌فرض (از جمله مسیر `/tmp/optibid-data.json`) فعال است.
- `npx tsc --noEmit` فقط یک خطا دارد: نبود `src/generated/source-snapshot.json`. این فایل gitignore شده و با `npm run typecheck`/`predev` خودکار ساخته می‌شود؛ با اجرای اسکریپت رسمی خطا ندارد.

## ۱۱. بدهی فنی و ریسک‌ها (به‌ترتیب اهمیت)

1. **رمز ادمین هاردکد** (`admin`/`1234`) — باید به متغیر محیطی یا جدول کاربران با هش منتقل شود.
2. **خروجی بیلد در گیت**: `.open-next` با ~۵۹MB و ۱٫۸۸۹ فایل کامیت شده؛ هر تغییر کد باعث دیف‌های سنگین می‌شود.
3. **دو فایل ZIP قدیمی** در ریشه (`optibid-ir-full-code-...zip` ۸٫۸MB و `parscoders_...zip`) — صرفاً آرشیو؛ ارزش نگه‌داشتن در گیت را ندارند.
4. **فایل‌های غول‌آسا**: `AdminDashboardClient.tsx` ۷٫۲۸۸ خط، `json-store.ts` ۵٫۹۹۰ خط، `store-product-import.ts` ۲٫۲۳۴ خط → تغییرات پرریسک و نقد‌پذیری پایین. شکستن تدریجی به ماژول توصیه می‌شود.
5. **بدون تست خودکار** (هیچ فایل تستی وجود ندارد) — منطق مالی/escrow و امتیازدهی بدون تست است.
6. **ذخیره‌سازی JSON**: نوشتن کل فایل برای هر عملیات و احتمال از دست رفتن داده روی `/tmp`؛ روی Workers هم KV یک کلید واحد است و race دارد.
7. **تاریخچهٔ گیت**: تنها یک کامیت — بازگشت به عقب و مرور تغییرات عملاً ممکن نیست.
8. `src/db` و اسکریپت‌های `patch_*.js`/`generate_php.js`/`zip_project.js` بازمانده‌اند و کد فعال نیستند.
9. **بدون داده اولیه**: سایت در حالت خالی همه‌جا پیام «هنوز …» نشان می‌دهد؛ برای دمو نیاز به seed است.

## ۱۲. پیشنهاد قدم بعدی (به‌ترتیب اثر)

1. ساخت **اسکریپت seed** برای داده نمونه (چند فروشنده/خریدار تاییدشده، درخواست، پیشنهاد، محصول فروشگاه) تا سایت قابل ارزیابی باشد.
2. **امن‌سازی**: انتقال رمز ادمین به `.env` + هش رمز، سخت‌تر کردن کوکی نشست.
3. **پاکسازی گیت**: حذف `.open-next` و ZIPها از ترکینگ و تصمیم دربارهٔ استراتژی دیپلوی.
4. **تست‌های پایه** برای escrow، کمیسیون، امتیازدهی و KYC.
5. کار روی بخشی که اولویت کسب‌وکار شماست (UI/UX فروشگاه، پنل فروشنده، ادمین، SEO…).
