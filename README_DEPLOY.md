# راهنمای دیپلوی OptiBid با ذخیره‌سازی JSON

## پلتفرم درست

این پروژه همچنان Next.js است. هنگام ساخت برنامه در PaaS یکی از موارد زیر را انتخاب کنید:

- Next.js ✅
- Node.js ✅

Flask، Python و PHP برای نسخه اصلی Next.js مناسب نیستند.

## دستورات استقرار

Build Command:

```bash
npm run build
```

Start Command:

```bash
npm run start
```

Port:

```text
3000
```

## ذخیره‌سازی داده‌ها با JSON

ثبت درخواست‌ها دیگر به PostgreSQL و `DATABASE_URL` وابسته نیست. داده‌ها در JSON ذخیره می‌شوند.

به صورت پیش‌فرض فایل JSON در این مسیر ایجاد می‌شود:

```text
/tmp/optibid-data.json
```

این مسیر روی اغلب PaaSها قابل نوشتن است، اما ممکن است بعد از ری‌استارت برنامه پاک شود.

## ماندگاری داده‌ها در PaaS

برای نگهداری اطلاعات بین ری‌استارت‌ها، یک Disk / Volume پایدار به برنامه متصل کنید و این متغیر محیطی را تنظیم کنید:

```text
OPTIBID_DATA_FILE=/PATH/TO/PERSISTENT-DISK/optibid-data.json
OPTIBID_UPLOAD_DIR=/PATH/TO/PERSISTENT-DISK/kyc-uploads
```

فایل JSON و پوشه مدارک KYC باید هر دو روی Disk پایدار باشند. تصاویر مدارک با AES-256-GCM رمزنگاری می‌شوند و خارج از مسیر عمومی سایت ذخیره می‌گردند.

مسیر دقیق Disk را از پنل PaaS خودتان دریافت کنید. می‌توانید فایل اولیه `data/optibid.json` را یک بار روی همان Disk کپی کنید؛ اگر فایل وجود نداشته باشد، برنامه فایل خالی لازم را ایجاد می‌کند.

## رمزنگاری اطلاعات بانکی

شماره حساب، کارت، شبا و حساب مقصد ادمین با AES-256-GCM در فایل JSON رمزنگاری می‌شوند. در تنظیمات محیطی PaaS یک کلید طولانی و ثابت تعریف کنید:

```text
OPTIBID_BANK_ENCRYPTION_KEY=یک-کلید-تصادفی-طولانی-و-محرمانه
```

این کلید را بعد از ذخیره داده‌ها تغییر ندهید؛ در غیر این صورت اطلاعات بانکی قبلی قابل رمزگشایی نخواهند بود. کلید را هرگز داخل Git یا فایل عمومی قرار ندهید.

## احراز هویت و فعال‌سازی حساب

1. خریدار یا فروشنده هنگام ثبت‌نام، نام کاربری و مدارک زیر را بارگذاری می‌کند:
   - تصویر کارت ملی
   - تصاویر صفحات شناسنامه
   - تصویر کارت بانکی
2. حساب با وضعیت `pending` و غیرفعال ساخته می‌شود.
3. کاربر تا قبل از تایید ادمین نمی‌تواند با نام کاربری یا ایمیل وارد شود.
4. ادمین در `/admin/dashboard` مدارک را مشاهده و تایید یا با درج علت رد می‌کند.
5. پس از تایید، حساب و نام کاربری فعال و اطلاعات بانکی تایید می‌شوند.
6. مدارک در `OPTIBID_UPLOAD_DIR` خارج از مسیر عمومی و با AES-256-GCM رمزنگاری می‌شوند.

## چرخه واقعی سفارش در JSON

1. خریدار درخواست را ثبت می‌کند.
2. درخواست فقط به فروشنده‌های دارای دسته‌بندی منطبق می‌رسد.
3. فروشنده حداکثر پنج درخواست مرتبط را در صف رادار می‌بیند و قیمت پیشنهاد می‌دهد یا رد می‌کند.
4. خریدار پیشنهاد را انتخاب می‌کند؛ سفارش با وضعیت `pending_payment` ایجاد می‌شود.
5. خریدار از کیف پول یا درگاه شبیه‌سازی‌شده پرداخت می‌کند؛ وجه در امانت قرار می‌گیرد.
6. فروشنده سفارش پرداخت‌شده را همراه کد رهگیری ارسال می‌کند.
7. خریدار دریافت را تایید می‌کند؛ کمیسیون محاسبه و باقی مبلغ به کیف پول فروشنده واریز می‌شود.
8. سفارش تکمیل‌شده یا لغوشده توسط هر طرف قابل بایگانی است.

  "ok": true,

}

## نکته مهم

JSON برای دمو، نمونه اولیه و تعداد کم کاربر مناسب است. برای پلتفرم واقعی با چندین کاربر همزمان، پرداخت، فاکتور رسمی و اطلاعات مالی، باید در نسخه نهایی دوباره از PostgreSQL یا دیتابیس مدیریت‌شده استفاده شود.
